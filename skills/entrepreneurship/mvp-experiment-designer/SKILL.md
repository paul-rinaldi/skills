# MVP Experiment Designer

Source method: FOR-M Workshop 2. An MVP is a scientific experiment testing core value. It is more about the process than the product. Strip away all features and polish, and keep it simple, cheap, and quick. The guiding question is: what do you need to learn?

## Mindset: Current Idea, Big Vision, MVP
First write the **Big Vision**: the big, bold, over-inflated version of the idea. Then go back to the **Current Idea**. The **MVP** is the smallest step from the current idea that tells you whether the vision holds.

## The five steps
1. **Write out the user experience vision.** Narrate a user going step by step through the finished product.
2. **Identify key assumptions.** For each step, ask what must be true. Sort the assumptions by risk (how likely they are to be wrong times how fatal that would be). Pick the riskiest one.
3. **Build an MVP to test that assumption.** Choose the cheapest type that can test it:
   - Product design: sketches, wireframes, mockups (Figma, Balsamiq)
   - Demo video: a short video that shows the idea
   - Landing page: a simple marketing page with a signup (Wix, Squarespace)
   - Crowd-funding: prove demand (Kickstarter)
   - Piecemeal: string existing services together (Google Forms, Sheets, Zapier)
   - Concierge: do the work manually, in person
   - Wizard of Oz: do the work manually behind a digital front end
   - Software prototype: actually code it, and only when the assumption is technical
4. **Measure results.** Before building, define the metric and the pass/fail threshold, for example "10 of 20 users complete signup."
5. **Pivot or persevere.** Decide against the threshold you set, not your feelings. Record what you learned and the next riskiest assumption.

## Output
One experiment card containing:
- The vision
- The ranked assumptions
- The chosen MVP type, with the reason it is the cheapest valid test
- The build steps and tools
- The metric and threshold
- The decision rule

If a hackathon deadline applies, also say which parts to fake (Wizard of Oz) for the demo and which parts must actually work.
